## ✅ TODO 11: Fix TOCTOU race condition in job cache

**What:** In `backend/app/modules/job_aggregator_service.py`, wrap all reads and writes to `_CACHE` with a `threading.Lock`. Pattern:
```python
_CACHE_LOCK = threading.Lock()
# On read:
with _CACHE_LOCK:
    cached = _CACHE.get(key)
# On write:
with _CACHE_LOCK:
    _CACHE[key] = result
```

**Why:** Multiple `ThreadPoolExecutor` workers can race on the same cache key simultaneously. Two threads can both see a cache miss, both fire API requests, and both write — last writer wins, wasting one full job fetch round-trip.

**Depends on:** Nothing. Independent fix.

## ✅ TODO 19: Add LRU eviction to job cache

**What:** In `job_aggregator_service.py`, replace the unbounded `_CACHE = {}` with an `OrderedDict`-based LRU evicting at `maxsize=50`:
```python
from collections import OrderedDict
_CACHE: OrderedDict = OrderedDict()
_CACHE_MAX = 50
# On write (inside lock):
_CACHE[key] = result
if len(_CACHE) > _CACHE_MAX:
    _CACHE.popitem(last=False)
```

**Why:** The current cache grows without bound. A server running for days with diverse search queries accumulates hundreds of stale entries. At 50 entries max with 5-minute TTL, memory footprint stays predictable.

**Depends on:** TODO 11 (lock must be in place before modifying cache structure).

## ✅ TODO 24: Wrap sync I/O with run_in_executor in async FastAPI handlers

**What:** In `backend/app/main.py`, for each `async def` route that calls synchronous blocking operations (e.g., `requests.get`, file reads, `ThreadPoolExecutor.submit`), wrap the sync call:

**Why:** Calling blocking I/O directly inside `async def` freezes the entire FastAPI event loop. One 8-second job scrape blocks all other concurrent requests for those 8 seconds.
